# The Wanderer's Core v0.2.0

Foundry v12 support. The module now runs on Foundry VTT 11 or 12 with the dnd5e system from 3.0 through 4.4,
including the dnd5e 4.x Activities model.

**Requirements:** Foundry VTT 11 or 12 (verified against 12), dnd5e 3.0 or later (verified against 4.4.4).
Foundry v13 is not supported yet.

**Install or update:** in Foundry open *Add-on Modules → Install Module* and paste

```
https://github.com/Sam-W-Jones/Wanderer/releases/latest/download/module.json
```

Worlds already running v0.1.x update from the Add-on Modules tab.

## What changed

- **dnd5e 4.x.** dnd5e 4.0 moved activation, targeting, damage, saves and consumption out of items into
  Activities and reshaped limited uses. On 4.x every rune is now built with a native activity (attack, save, heal,
  damage, check or utility; Hammerstone gets an attack and a save), limited uses in the 4.x spent/max/recovery
  form, and an item-uses consumption target so a rune spends its own use when activated. Weapon runes carry their
  base damage the 4.x way. On dnd5e 3.x the classic item fields are built exactly as before.
- **Linked features on 4.x.** Unstable Core II spends Overload's charge, and Search the Core spends a use of
  Rage, through the activity's consumption target; Overload's short-rest recovery while Unstable Core II is carved
  is set through a 4.x recovery profile and restored when the rune is pried out.
- **The compendium reads under either system.** The shipped *Wanderer Runes & Cores* items carry both data shapes;
  each system keeps the fields it knows and drops the rest. Runes carved under dnd5e 3.x are converted by dnd5e's
  own migration when the system is upgraded to 4.x.
- **Riders** read dnd5e's magical bonus, the 3.0 attack bonus, a 4.x attack activity bonus or the name, and the
  node copy of a +N weapon has its 4.x base damage bonus stripped as well.
- **Foundry v12.** Active Effects carry both the v11 `icon` and the v12 `img` field; the manifest allows v12.
- The headless smoke test now runs under the dnd5e 3.0.4, 3.3.1 and 4.4.4 item models in CI.

## Audit

An independent review walked every field the module emits through the dnd5e 4.4.4 schemas and migrations, the
dnd5e 3.0.4 bundle and Foundry's data-model code. It found nothing that breaks on either system or on v12 core,
and four silent-behaviour issues, all fixed in this release:

- Carved runes and seated cores no longer inherit dnd5e 4.x's `migratedUses` bookkeeping from the compendium
  copy, which a later world migration would have turned into a refund of spent uses.
- Removing a rune that another rune spends (Overload while Unstable Core II is carved) now unlinks the dependant
  instead of leaving a dangling consumption target and a permanent sheet warning; re-carving links it again.
- An essence harvested under dnd5e 3.x and slotted after an upgrade to 4.x is run through dnd5e's own migration
  first, so its activation survives as an activity.
- A core option with nothing to activate no longer reports a Rage link it did not make.

Expected on 4.x, not a bug: Hammerstone has an attack and a save activity, so using it from the sheet asks which
one first.

## First-run checklist

1. Enable the module, open the sheet as GM, press **Core**, confirm the designation.
2. Seat Core of the Wanderer; the sheet should show the feat with Search the Core linked to Rage.
3. As the player, carve Titan's Grip, press **Work**, and confirm the button locks and the chat line appears.
4. GM **Finish now**; confirm the sphere icon, the attunement maximum dropping by one, and the feature on the sheet.
5. On dnd5e 4.x, open a carved active rune and confirm its activity on the item sheet; use it from the sheet and
   confirm the use is spent.
6. Disenchant a +1 weapon, slot the essence, and confirm the rider effect on the actor's Effects tab.
7. Long rest as the player; confirm the day resets and the Awakened Core prompt appears.
8. Carve Overload, then Unstable Core II; use Unstable Core II and confirm Overload's use is spent.

## Known limitations

- Foundry v13 is not supported (Application v1 and the scene-control format change there).
- The Awakened Core prompt appears on the client that performed the long rest.
- Verified headlessly against the dnd5e 4.4.4 and 3.0.4 data models, but not yet played through in a live
  Foundry v12 world. Anything odd belongs on the
  [issue tracker](https://github.com/Sam-W-Jones/Wanderer/issues).
